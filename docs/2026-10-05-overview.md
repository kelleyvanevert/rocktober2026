# Overview, 5 October 2026

What changed today, on top of [3 October](2026-10-03-overview.md) and
[4 October](2026-10-04-overview.md): a new syntax built around **params**,
effects as values, and a UI with documentation that follows the cursor.

## The idea

Every node has params, every param has a name and a default, and a param
stays *free* until it's set. Composing nodes doesn't close their params, so
a composed sound still has the free params of its parts, and they can be set,
or linked, afterwards, all at once.

```
wavetable                                   -- a node, all defaults: a sine
wavetable:pos(0.3):note(g3)                 -- set two of its params
(wavetable + wavetable:table("sine-saw")):note(g3)   -- g3 for every free note
```

`x:name(value)` sets **every free param called `name`** in `x`, however deep in
it. Once set, a param isn't free any more, so an outer `:name(...)` only
reaches the ones still open (and is an error if there are none: that's
usually a typo).

`?name` makes a new free param. Setting a param to something with a `?name`
in it *links* it:

```
(wavetable + wavetable:table("sine-saw")):note(?note + swoop)
```

The two `note`s are filled with `?note + swoop`, and the sound now has one
new free `note` (the outer one). Setting that later reaches through to both.

## Syntax

```
let swoop = mod("swoop"):retrig * 9 - 1

let wub = (
    (wavetable + 0.6 * wavetable:table("sine-saw"):pos(0.6)):note(?note + swoop)
        * lowpass:freq(?note + 24 + swoop * 3)
        * drive:power(6)
        * envelope("wub")
        * 0.6
):note(glide(?note):dur(300ms))

wub:note(g2).play("wub", at 5b)
notes("x . x .", 0.25b).play(wub, "kick", at 5b)
```

- **A bare name is a node with its defaults**: `wavetable`, `lowpass`,
  `noise`. Arguments fill its params *in order*: `wavetable("sine-saw", 0.6)`
  is `wavetable:table("sine-saw"):pos(0.6)`. That's what makes resource
  references read like before: `sample("kick.mp3")`, `envelope("pluck")`,
  `mod("sweep")`, `reverb("plate")`.
- `x:name(value)` sets params; `x:name` alone is `x:name(1)`, for switches
  (`mod("sweep"):retrig`). It binds like a method call, tighter than any
  operator.
- `x.f(a)` is still `f(x, a)`, now only for operations that aren't nodes:
  `.play`, `.fit`, `.slice`, `.delay`, `.repeat`, `.range`, `.round`,
  `.scale`, `.map`, and calling your own functions. `x.play` and `x.play()`
  are the same.
- Operators: `+ - * /`, with the usual precedence; `-x` is `-1 * x`. A `-`
  right after something that ends an expression is a minus (`9 - 1`, `9 -1`),
  otherwise it's a number's sign (`f(-1)`, `* -6db`).
- `[a, b, c]` is a list, and `n => n * 2` a function of one parameter. A list
  of sounds plays as their mix, and `:name(...)` on a list sets it in all of
  them:

  ```
  [0, 3, 7, 10].map(n => saw:note(?note + n)):note(c3)
  ```

- A name followed by `(` **on the same line** is a call. On the next line
  it's a new statement, which fixes the old gotcha where `let a = b` followed
  by a line starting with `(` read as `b(...)`.
- Unchanged: `let`, `fn name(a, b) = ...`, `?name = default`, notes (`c3`,
  `f#4`), units (`500ms`, `0.25b`, `1bar`, `-6db`, `800hz`, `0:11:188`), `at 4b`,
  `notes("c2 e2 _ .", 0.25b)`, `.play(...)` with a slot and a grid.

## Effects are values

An effect on its own (`lowpass`) is a sound with an open input. Multiplying
applies it:

```
sound * lowpass:freq(800hz)      -- the sound, filtered
lowpass * drive                  -- an effect: a lowpass into a drive
let rumble = reverb("hall"):mix(1) * bandpass:freq(f2):res(0.6) * drive:power(12)
kick * rumble
```

`a * b` is: `b` applied to `a` if `b` is an effect; a gain if either is a
control or a number; ring modulation if both are sounds. Playing an effect
without an input is an error that says so.

## Nodes and their params

Defaults in parentheses. **Bold** params are filled by arguments first.

| node | params |
|---|---|
| `wavetable` | **table** ("basic"), pos (0), warp (0), note (c3) |
| `sine`, `triangle`, `saw`, `square` | **warp** (0), note (c3): a wavetable with table "basic" at pos 0, ⅓, ⅔, 1 |
| `noise` | **color** ("white"): white, pink, brown, blue, violet |
| `sample` | **file** (required), start (0), end (unset: the end) |
| `lowpass` | **freq** (2khz), res (0) |
| `highpass` | **freq** (200hz), res (0) |
| `bandpass` | **freq** (1khz), res (0) |
| `pan` | **side** (0): -1 left to 1 right |
| `spread` | **width** (0.5) |
| `drive` | **power** (4) |
| `echo`, `pingpong` | **time** (0.75b), feedback (0.5), mix (0.35), low (80hz), high (10khz) |
| `reverb` | **space** ("hall", or a sound), mix (0.3) |
| `duck` | **key** ("kick"), depth (0.8), release (150ms), threshold (-20db) |
| `limit` | **ceiling** (-1db) |
| `envelope` | **env** (required), gate (unset: the note's length, or never) |
| `mod` | **mod** (required), repeat (1; inf loops), retrig (0), latch (0) |
| `random` | **every** (1b), retrig (0), latch (0) |
| `glide` | **target** (required), dur (100ms), legato (0) |

The specs, with a line of documentation per param, are in
`engine/src/spec.rs`; the editor shows them.

**One name, one meaning.** Since a name reaches every free param of that name,
built-ins don't share a name for different things: `pan:side` (not `pos`,
which is the wavetable's), `spread:width`, `duck:depth`. Shared names are
shared on purpose: `note`, `mix`, `freq`/`res` across filters, `retrig` and
`latch` across modulations and randoms (`steel:retrig` restarts every
modulation in `steel` on each note).

The same goes for params you make yourself: in `synths.rock`'s
`filter_delay`, the bands are `?lo`, `?mid` and `?hi`, because `?low` and
`?high` would also reach the echoes' own `low` and `high`.

## Kinds of params

- **Controls** (pos, note, freq, depth, ...) can change while a sound plays
  and can be linked. A free control param is a hole named after the param,
  holding its default.
- **Settings** (table, file, time, space, retrig, ...) are fixed when the code
  runs. They're set with plain values; setting one loads what it refers to
  right then (a sample, a table, a space), so nothing is loaded while voices
  are being built.

## Defaults of linked params

- `:note(?note + 12)`: a `?note` without a default takes the default of the
  `note` it fills. Under another name (`:note(?pitch)`) it's a param of its
  own, with no default.
- A hole without a default borrows one from a hole with the same name:
  `sine * lowpass:freq(?note + 24)` has two `note`s, and the lowpass's takes
  the sine's c3. Holes that have a default of their own keep it (the docs
  show the first one found).
- A param with no default anywhere has to be set before the sound can play
  ("play: ?pitch has no value (set it with :pitch(...))").

## Patterns, notes and glide

A pattern fills the instrument's free `note` with each note, as `with(note:
...)` did. If the note was set (`sine:note(c3)`), the pattern can't reach it,
and says so.

`glide(?note):dur(300ms)` follows its target, sliding to each new value:

- By default every note is a new voice (its envelope starts over) that slides
  in from the note before.
- `:legato` makes the notes up to a rest one voice, sliding along: the old
  `pattern.glide(...)`. (The whistle in `journey.rock` uses this.)
- Elsewhere (on a modulation, say) it's a smoother: it lags behind.

## Typing

No static type checker was needed. Every expression is evaluated eagerly,
when the code runs, to a concrete description, so a composed sound's free
params are always known exactly (`Sound::free_params`), with their nodes'
types. A param's type is checked when it's set; an unknown or already-set
name is an error that lists the free params. Static inference would only be
needed for params set from code that hasn't run yet, and nothing here does
that.

## Engine

- `spec.rs`: the built-in nodes and functions, their params, defaults and
  docs (`Spec`, `ParamSpec`, `Doc`).
- `desc.rs`: `Sound` and `Control` descriptions (they used to live in
  `eval.rs`). A built-in is a generic `Node { spec, args, free, resolved, input }`,
  so setting, listing and documenting params is the same code for every node.
  `Mapper` rewrites descriptions.
- `eval.rs`: values, built-in functions, `Assign` (setting params by name),
  and `resolve` (loading what settings refer to).
- `control::Glide`: a linear slide to each new value of its input.
- The scheduler gives non-legato glides the previous note, and plays legato
  sounds a voice per phrase.
- `Session::describe(name)`: docs for a built-in, or for a `let` (its free
  params).
- `repl code <file.rock>` / `repl set-code <file.rock> <code.txt>` read and
  replace a file's code, keeping its resources.

## The app

The code editor fills the left of the window. The right column has three
panels: **documentation** for the name under the cursor (a built-in's params
and examples; a `let`'s free params with their defaults; for `:name`, which
nodes have that param), the **editor** for the resource under the cursor
(sample, envelope, modulation), and the **logs**. The status bar runs along the
bottom.

## Old → new

| before | now |
|---|---|
| `wavetable("basic", 0.2, 0, ?note)` | `wavetable:pos(0.2)` (or `wavetable("basic", 0.2)`) |
| `lead.with(note: c2)` | `lead:note(c2)` |
| `x.lowpass(800hz, 0.5)` | `x * lowpass(800hz, 0.5)` or `x * lowpass:freq(800hz):res(0.5)` |
| `x.gain(-6db)`, `x.gain(env)` | `x * -6db`, `x * env` |
| `x.reverb("hall", 0.4)` | `x * reverb("hall"):mix(0.4)` |
| `x.echo(0.75b, 0.3, 0.2)` | `x * echo(0.75b, 0.3, 0.2)` |
| `x.pan(-1)`, `x.spread(0.6)`, `x.drive(6)` | `x * pan(-1)`, `x * spread(0.6)`, `x * drive(6)` |
| `x.duck("kick", 0.9, 500ms)` | `x * duck("kick", 0.9, 500ms)` |
| `x.limit` | `x * limit` |
| `modulation("m").repeat(inf)` | `mod("m"):repeat(inf)` |
| `.retrig`, `.latch`, `.free` | `:retrig`, `:latch`, (the default) |
| `envelope("e").gate(60ms)` | `envelope("e"):gate(60ms)` |
| `pattern.glide(300ms).play(lead)` | `pattern.play(lead:note(glide(?note):dur(300ms):legato))` |
| `noise()` | `noise` |
| `x + -1` | `x - 1` |
| `add(a, b)` | `a + b`, `add(a, b)` or `[a, b]` |

Old names give errors that say what to write instead.

## Not yet

- A param set on a sound can't be un-set; there's no "override" of a set
  param. (Decided today: set means consumed.)
- Settings can't be linked (`wavetable:table(?t)` is an error): they're fixed
  when the code runs, so they'd need evaluating again per note.
- Docs for `?name` params made in your own code are only their name and
  default.
- Lambdas take one parameter; functions can't be passed to `fn`s yet.
