# Overview, 3 October 2026

A snapshot of the language and the engine as they are, plus the design
decisions made today for where they're going. Meant to be revisited, not kept
up to date: when things change, write a new dated overview.

## Crates

| crate | what |
|---|---|
| `crates/engine` | parser, evaluator, audio nodes, audio thread, recorder. No UI. |
| `crates/app` | the editor (`gpui-kit`): code editor, console, status bar. |
| `crates/repl` | a line-by-line REPL over stdin, for quick tests without the UI. |

## The language (as of today)

### Syntax

A program is a sequence of expressions (statements). There is exactly one kind
of compound expression: a call.

```
sample("kick.mp3").fit(500ms).repeat(4).play     -- comment
play(repeat(fit(sample("kick.mp3"), 500ms), 4))  -- the same thing
```

- `x.f(a, b)` is sugar for `f(x, a, b)`, and `x.f` for `f(x)`. The parser
  rewrites method calls to plain calls, so both styles mix freely. (This means
  `120.bpm` is `bpm(120)` for free.)
- Literals:
  - strings: `"kick.mp3"`
  - numbers: `4`, `.5`, `-0.5`, `inf`
  - durations: `500ms`, `2s`
  - time positions: `m:ss`, `m:ss.fff` or `m:ss:mmm` (`0:11:188` is 11.188 s).
    Lexed as durations.
  - decibels: `-6db`. Converted to an amplitude factor *in the lexer*, so after
    lexing it's just a number.
- Comments: `--` to end of line.
- Trailing commas are allowed in argument lists.
- Every expression carries its byte offset (`Spanned::pos`), for error messages.

The parser (`engine/src/lang.rs`) knows nothing about what functions mean; it
just builds the tree.

### Values and evaluation

`engine/src/eval.rs` turns the tree into values. Today the value types are:
`Sound`, `Str`, `Num`, `Duration` and `Nothing`. Each function is a hand-written
`match` over the argument values, which also produces the error messages
("fit: expected a duration (like 500ms), got a number").

A `Sound` is a cheap, immutable **description** of a sound: a tree of
`Sample`, `Fit`, `Slice`, `Delay`, `Repeat`, `Add`, `Seq`, `Gain`, `Limit`,
`Reverb`. Only `play` turns a description into live, stateful audio nodes
(`Sound::instantiate`). So a description can be stored, reused, or played many
times at once, each play getting fresh playback state. This split is the
foundation for instruments (see below): an instrument is a description with
holes, instantiated once per note.

Evaluation of a block is all-or-nothing: commands are only sent if every
statement evaluates, so a typo never half-plays a block.

### Functions

```
node.play
stop()

sample(file[, start[, end]])     -- decodes only start..end of the file
add(...sounds)                   -- mix, as long as the longest
seq(...sounds)                   -- one after another

sound.gain(amount)               -- factor or decibels
sound.fit(duration)              -- pad with silence or cut (with a short fade)
sound.slice(start, end)
sound.delay(duration)
sound.repeat(times)              -- a whole number, or inf
sound.limit([ceiling])           -- lookahead limiter, default -1 dBFS
sound.reverb(space[, mix])       -- a preset name, or a sound used as the IR
```

Reverb presets are synthesized (decaying stereo noise, highs decaying faster):
see `reverb::preset_names()`. A sound as the space is rendered on the app thread
and used as the impulse response.

Samples are looked up next to the code file, then the working directory, each
with and without a `samples/` subfolder (`workspace::sample_dirs`). Decoded
samples are cached per (file, window).

## The engine (as of today)

```
app thread                                          audio thread (cpal callback)
──────────                                          ────────────────────────────
text ─▶ parse ─▶ eval ─▶ Sound (description)
                          │ play: instantiate
                          ▼
                  Box<dyn Node> ── commands (rtrb) ─▶ Engine::process:
                  (built, allocated,                   pop commands, mix voices,
                   samples decoded)                    retire finished ones
                                                          │
       garbage thread drops it ◀── garbage (rtrb) ────────┘
```

- **Two threads, SuperCollider-style.** The audio thread never allocates, locks,
  prints or touches files. Everything is built on the app thread and handed over
  through a lock-free SPSC queue (`rtrb`). Finished nodes travel back through a
  second queue and are freed on a garbage thread, because `free()` may lock.
- **Pull-based nodes.** `trait Node { process(&mut [Frame]) -> usize; reset();
  skip(frames) }`. A node writes up to `out.len()` stereo frames and returns how
  many; fewer means it's finished. `skip` lets slicing jump ahead without
  rendering. Timing *within* one node tree is sample-accurate: `seq`, `delay`
  and `repeat` count frames.
- **Engine.** Up to 256 voices, blocks of up to 1024 frames. `StopAll` fades
  every voice out over 10 ms. The mix is clipped to ±1 before it goes to the
  device *and* the recorder, so recordings are exactly what was heard.
- **Commands**: `Play(node)`, `StopAll`, `StartRecording(producer)`,
  `StopRecording`. There's no notion of time yet: everything plays *now*.
- **Recorder.** The audio thread pushes interleaved samples into a 4 s queue; a
  writer thread writes a WAV and updates its header every second.
- **Reverb.** Uniformly partitioned FFT convolution (256-frame partitions).
- **Status.** Voice count etc. via atomics, which the UI polls.
- **Build profile.** The engine and all dependencies are optimized even in
  debug builds, since audio has to keep up in real time; the app crate stays
  unoptimized for fast rebuilds.

## The app (as of today)

One window: code editor, console (log), status bar (file, recording, voices).

| key | action |
|---|---|
| cmd-enter | run the selection, or the block (run of non-blank lines) under the cursor |
| cmd-shift-enter | run everything |
| cmd-. | stop all sound |
| cmd-r | start/stop recording to `recordings/` |
| cmd-s | save |

Comments are greyed out, errors get a squiggle at their position, and the code
that just ran is flashed. `crates/app/tests/ui.rs` drives the real UI headlessly
and writes screenshots to `target/ui-snapshots/`.

## Decisions made today (not built yet, unless noted)

### Types

Nominal types, a small set of traits, and the main split is by **rate**:

- `Audio`: stereo, sample rate. What `play` takes. `Sample`, `Wavetable` and
  all current nodes.
- `Control`: mono f32 stream, nominally 0..1. `Modulation`, constants, holes.
- `Envelope`: *not* itself a Control. It's a shape waiting for a gate; bound to
  a voice's gate (or an always-open gate, for a drone) it becomes a Control.
- Units and plain values: `Number`, `Duration`, `Time` (a position, like
  `0:02:254`), `Decibels`, `Pitch` (`c2`), `String`.
- Resources: `Midi`, `Wavetable`, ...

What the traits buy us now: operator overloads (`Audio * Control → Audio`,
`Control * Number → Control`, `Control + Control`, `Audio * Audio` for ring
modulation), and a few lossless coercions (`Number → Control`,
`Decibels → gain`, `Pitch → Hz`).

Audio and Control are deliberately separate, unlike SuperCollider's single
UGen type: it catches mistakes ("you played a modulation") and makes overloads
resolve cleanly, at the cost of an explicit conversion for audio-rate FM/AM.

No static checker yet (there are no variables or lambdas to check). The plan:
replace the hand-written `match` in `eval.rs` with a signature table per
function, dispatch on argument types at runtime, and generate the error
messages from the signatures. The same type definitions become a static checker
later, when holes need their types inferred.

Engine side: `trait ControlNode` mirrors `Node` but is mono,
`process(&mut [f32]) -> usize`, computed per sample (no control-rate decimation)
until that turns out to be too slow.

### Parameters accept value sources

Every numeric parameter of every node accepts a `Control`; a plain number is a
constant Control. Value sources differ along two axes:

| | continuous | sampled at note-on, held |
|---|---|---|
| **global clock** (free-running, shared by voices) | a modulation sweeping a drone | each note gets the sweep's current value |
| **voice clock** (restarts every note) | envelope, retriggered modulation | (a constant per note) |

Three levels of interface on top of that:

1. **Direct**: a control in a slot, `wavetable("basic", modulation("sweep"), 0, c2)`.
2. **Holes**: a value supplied later, by a note event or a binding.
3. **Live instances** (later): re-binding a hole on something already playing,
   like SC's `Ndef.map` or Ableton's mod matrix.

Engine side, a slot is one of: a constant, a per-voice `ControlNode`, or a
global control bus that all voices read (latching = reading the bus once when
the voice starts).

### Holes and instruments (syntax "option A")

```
let lead = wavetable("basic", ?pos = 0.2, ?warp, ?note) * envelope("pluck")

lead.with(warp: 0, note: c2).play                       -- a drone
lead.with(pos: modulation("sweep"), warp: 0, note: c2).play
notes("c2 e2 g2 b2", 1/8).play(lead.with(
  pos:  modulation("sweep").retrig,   -- restarts on every note
  warp: modulation("wobble").latch,   -- sampled at note-on, held
))
```

- `?name` is a hole, `?name = value` gives it a default.
- `let` binds a name on the app side (new syntax).
- Binding holes is **functional**: it returns a new description, still possibly
  with holes left open (partial application). Nothing is instantiated until
  `play`, once per voice. Calling it twice gives two independent instruments.
  Called `.with`, since it usually leaves holes open (partial application).
- Holes are audio-thread controls, not app-side function parameters, and the
  syntax keeps those apart. (SuperCollider conflates them: SynthDef arguments
  look like function arguments, and math on them looks like language math but
  builds UGens.)
- Built-in voice holes `?note`, `?vel`, `?gate` are filled by note events
  (gate defaults to open, so `play` without notes is a drone). `envelope(...)`
  reads `?gate` implicitly.
- Playing something with an unbound hole that has no default is an error
  ("lead has unbound ?warp").
- An instrument is a `Sound` with holes; `instantiate` gets the event's
  bindings.

### Clock and scheduler

The SuperCollider / Tidal / Strudel split:

- **Audio thread owns the true clock**: a frame counter, published atomically.
  New command `PlayAt { frame, node }`; the engine keeps a small sorted pending
  list and starts each node at its exact offset inside the block.
- **App thread owns musical time**: tempo, beats, bars. A scheduler wakes every
  ~25 ms, collects the events in `[now, now + ~100 ms]`, converts beats to
  frames, and sends `PlayAt`s. The lookahead absorbs UI stalls.
- Not chosen: running the scheduler on the audio thread (Max/Pd style), since
  it would make pattern logic allocation-free, which doesn't fit arbitrary code.

The syntax this surfaces: `120.bpm`, beat-based durations, `play` quantizing to
the next bar by default (more interesting options later), and optionally named
slots so re-running a block replaces it instead of stacking:
`.play("drums")`. Unnamed plays just stack and can't be replaced. (Naming is a
stopgap; identifying a block by its position is nicer but fragile while
editing.)

### Wavetable synth

`wavetable(table, position, warp, pitch)`:

- **table**: a resource. Built-ins synthesized here (sine→square, sine→saw,
  sine→triangle, a pulse-width sweep, ...), plus any Serum-style WAV (frames of
  2048 samples) in `wavetables/`. Ableton's own tables ship with Live under its
  licence, so they aren't bundled.
- **position**: 0..1 (Ableton shows 0–100%). Bipolar -1..1 is for modulation
  *amounts*, not parameters.
- **warp**: 0..1, a phase distortion that bends the read phase so energy
  bunches up in part of the cycle (Ableton's exact algorithm isn't public).
  Fold maybe later.
- **pitch**: absolute (`c2`). Transposing is relative to a note, so it's an
  operation on pitch, not a parameter.
- Anti-aliasing: per frame, a band-limited copy per octave (FFT, `realfft`),
  crossfading between frames and octaves. 2× oversampling only if warp aliasing
  is audible.

### Resources and their editors

Resources are data that doesn't belong in code, referenced by name:
`sample("kick.mp3")`, `envelope("pluck")`, `modulation("sweep")`,
`wavetable("basic")`, `midi("melody")`. One folder per kind, next to the code
file: `samples/`, `envelopes/`, `modulations/`, `wavetables/`, `midi/`.
Envelopes and modulations are small JSON files, so they diff well in git.

When the cursor is on a resource reference, the reference is highlighted and an
editor for it opens in a panel at the bottom. If the file doesn't exist, the
panel says so and offers to create it (samples: drop a file to copy it in).

- **Sample editor**: the waveform, its duration, the time under the mouse;
  clicking copies that time in the language's own format (`0:02:254`), ready to
  paste into `sample(...)`.
- **Modulation editor**: one value (0..1) over a fixed length (a setting of the
  modulation). Points with curved segments: click to add a point, drag to move,
  alt-drag a segment to curve it, alt-click a point to remove it.
- **Envelope editor**: ADSR with a slope per segment, like Ableton's. It looks
  like a modulation editor but isn't one: its x-axis is not one timeline. The
  attack/decay part is time since note-on, the sustain is a level held for as
  long as the note lasts (unknown while editing, so drawn at a fixed width), and
  the release is time since note-off, starting from whatever level the
  envelope was at. So: two separate data models and two widgets, sharing the
  curve-segment math (drawing a sloped segment, dragging its slope).
- **MIDI editor**: later; it needs its own design.

#### Built today

The panel and the sample, envelope and modulation editors exist (wavetable and
MIDI references open the panel, which says there's no editor yet). Nothing
*plays* envelopes or modulations yet; that needs `ControlNode` and the
parameter slots above.

File formats (`engine/src/envelope.rs`, `engine/src/modulation.rs`). Times are
in seconds; curves are -1..1, where 0 is straight, positive starts slow, and
negative starts fast (like a natural decay), see `curve::bend`.

```json
// envelopes/pluck.json
{
  "attack":  { "time": 0.001, "curve": 0.0 },
  "decay":   { "time": 0.6,   "curve": -0.5 },
  "sustain": 0.5,
  "release": { "time": 0.6,   "curve": -0.5 }
}

// modulations/sweep.json: `at` is a fraction of the length, so changing the
// length stretches the shape. Each point's curve shapes the segment after it.
{
  "length": 2.0,
  "points": [
    { "at": 0.0, "value": 0.0, "curve": 0.0 },
    { "at": 1.0, "value": 1.0, "curve": 0.0 }
  ]
}
```

#### Built today, part 2: controls

- **Operators.** `a * b` is `mul(a, b)`, `a + b` is `add(a, b)`; method calls
  bind tightest, then `*`, then `+`, and parentheses group:
  `(sample("x") * envelope("pluck").gate(300ms)).play`.
- **Types and signatures**, as planned above: `eval.rs` has a `Type` per value
  (`Sound`, `Control`, `Envelope`, `Number`, `Duration`, `String`), with
  `Number → Control` and `Envelope → Control` as the only implicit
  conversions. Every function is a list of signatures; the first that fits
  runs, and errors name what the closest signatures expected
  ("mul: expected a sound or a control, got a string").
- **Controls** (`engine/src/control.rs`): `trait ControlNode`, mono and per
  frame, finishing like audio nodes do. `Param` is a node parameter that's a
  constant or a control; `Gain` uses one.
- New functions and overloads:

  ```
  envelope(name)              -- an Envelope; as a control, it never releases
  envelope.gate(duration)     -- a Control: released after `duration`, then it ends
  modulation(name)            -- a Control: plays once, then holds its last value
  modulation.repeat(times)    -- loops (`repeat(inf)` makes it an LFO)

  sound * control, control * sound, sound.gain(control)   -- shaped by the control
  sound * sound                                            -- ring modulation
  control * control, control + control                    -- combined
  number * number, number + number                         -- plain arithmetic
  ```

- A sound times a control ends when either ends, so a gated envelope ends its
  sound after the release.
- Every control starts when the sound it shapes starts (the voice clock).
  Global, free-running controls (control buses) and latching come with
  instruments and notes.
- Envelope and modulation files are read every time the code runs, so edits
  in the editor apply the next time you run it.
- `Resources` (`resource.rs`) bundles the code folder with the sample
  folders, and `Session::start` takes one.

#### Built today, part 3: wavetables, holes, `let`

```
wavetable(table[, position[, warp[, pitch]]])   -- defaults: 0, 0, c4
let lead = wavetable("basic", ?pos = 0.2, ?warp, ?note) * envelope("pluck").gate(400ms)
lead.with(warp: 0.3, note: c2).play
lead.with(warp: modulation("wobble").repeat(inf), note: c3).play
```

- **Notes** are literals: `c2`, `f#3`, `eb4`, `b3`. They're MIDI note numbers,
  with `c4` = 60 = middle C (Ableton calls that C3). A pitch converts to a
  control, so `c3 + 7` or `c3 + modulation("vibrato") * 0.3` work wherever a
  pitch is expected. Single-letter-plus-digit names (`a1`, `b3`) are therefore
  notes, not names.
- **`let name = value`** names a value for the rest of the session, so one
  block can define an instrument and others play it. A block that fails
  changes nothing, `let`s included. A bare name refers to it.
- **Holes**: `?name` is a control to be filled in later, `?name = 0.2` one with
  a default. `.with(name: value, ...)` fills holes and returns a new
  description (partial application), so filling the same instrument twice
  gives two independent sounds. Filling a hole that isn't there, or playing
  one that has no value and no default, is an error that names it.
- **Wavetables** (`engine/src/wavetable.rs`): frames of 2048 samples, stored at
  11 bandwidths (one per octave), crossfaded by pitch so high notes don't
  alias. Warp is CZ-style phase distortion (the first half of the cycle is
  squeezed into less time); the bandwidth level accounts for it. Built-ins:
  `basic` (sine → triangle → saw → square), `sine-square`, `sine-saw`, `bright`
  (sine to saw by adding harmonics, like opening a filter) and `pulse` (width
  50% → 2%). Any Serum-style WAV in `wavetables/` works too, and overrides a
  built-in with the same name. One oscillator runs ~1000× faster than real
  time.
- Parsing gotcha: a name followed by `(`, even on the next line, is a call,
  so `let a = b` followed by a line starting with `(` reads as `b(...)`.
