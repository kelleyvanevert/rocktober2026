# Overview, 4 October 2026

What was added today, on top of [the 3 October overview](2026-10-03-overview.md).
Prompted by recreating the first 30 seconds of an old Ableton track
(`journey.rock`), which needed noise, filters, width, echoes, glides and
sidechaining, and is in 5/4.

## Timing: `play` starts right away, or on a grid

```
x.play                        -- right away
x.play("bass")                -- right away, replacing what played in "bass"
x.play(at 4b)                 -- on the next multiple of 4 beats
x.play("bass", at 1bar)       -- the same, named
x.play(at 5b + 2)             -- beats 2, 7, 12, ...: the 5/4 grid, 2 beats in
pattern.play(lead, "lead", at 5b)
```

- `at 4b` is a **grid**: every 4 beats, counted from beat 0, so everything on
  the same grid stays in step however late it was started. `at` binds like a
  method call, so `at 5b + 2` is `add(at(5b), 2)`; the offset is in beats
  (`2` or `2b`). `4b` alone is still just a length.
- "Right away" is 50 ms from now (`START_MARGIN_SECONDS`): the next audio
  block has to pick the command up, and starting any sooner would make the
  first note late, out of step with the rest of its pattern. Everything in one
  run starts at the same moment, so cmd-shift-enter still starts a whole file
  in step. The first notes of a pattern are sent right away, not on the
  scheduler's next tick.
- cmd-. stops a block's named slots on the grid its `play` was written with
  (read from the code: `eval::named_slots`), or right away.
- `StopSlot` now also cancels the slot's voices that were sent ahead but would
  start at or after the stop. Before, re-running a block within the
  scheduler's lookahead (100 ms) could double the first notes; with bars that
  couldn't happen, with "right away" it can.
- The clock is still 4/4 for the status bar's bar.beat, and `1bar` is still 4
  beats. Odd meters are grids: `at 5b`.

`folk.rock` and `dnb.rock` now play `at 1bar`, so parts can be brought in one
by one as before; `journey.rock` plays `at 5b`.

## Sources and effects

```
noise(["white" | "pink" | "brown" | "blue" | "violet"])
sound.lowpass(cutoff[, resonance])     -- also highpass, bandpass
sound.pan(position)                    -- -1 left .. 1 right
sound.spread([amount])                 -- 0..1, default 0.5
sound.echo(time[, feedback[, mix[, low[, high]]]])
sound.pingpong(...)                    -- the same, bouncing left/right
sound.duck(slot[, amount[, release]])  -- default 0.8, 150ms
```

- **Frequencies are pitches.** A cutoff is a note number, like an
  oscillator's pitch, and `800hz` / `2khz` is another way to write one (the
  lexer converts it, the way it converts `-6db` to a factor). So cutoffs sweep
  evenly (`40 + modulation("sweep") * 80`), follow the note
  (`?note + 24`), and `c6` works. A plain number above 140 as a cutoff is an
  error suggesting `hz`.
- **Noise** (`noise.rs`): xorshift white, Paul Kellet's pink, a leaky
  integrator for brown, and differences of pink/white for blue/violet, all at
  about the loudness of a wavetable. Mono, like the oscillators; seeds are
  handed out in order, so a program renders the same every time.
- **Filters** (`filter.rs`): a TPT state-variable filter, 12 dB/octave, stable
  under fast modulation. Resonance 0..1 maps to Q 0.707..25 on a log scale;
  the bandpass is normalized to a 0 dB peak.
- **Spread** (`fx.rs`): a stereo chorus, two voices per side, the right side's
  LFOs half a cycle behind the left's, which is what makes the sides differ.
- **Echo** (`fx.rs`): a stereo delay with feedback; every repeat passes through
  a highpass (`low`, default 80hz) and a lowpass (`high`, default 10khz), so
  the repeats thin and darken as they fade, like Ableton's Echo. Ableton's
  *Filter Delay* is something else: three delays (L, L+R, R) each with a
  bandpass *before* it. That's a composition here:
  `add(x.bandpass(400hz).echo(0.5b, 0.6, 1).pan(-1), x.bandpass(2khz).echo(0.75b, 0.6, 1).pan(1))`.
- **Duck** (`sidechain.rs`): `pad.duck("kick")` turns the pad down while
  whatever plays in the slot named "kick" sounds. It reacts to whether the key
  sounds (above -40 dBFS, held through zero crossings), not how loud: a fast
  attack to `1 - amount`, and back up over `release` once the key is quiet.
  Like a volume shaper triggered by the kick, so ghost notes duck as deep as
  accents.

### How sidechaining works in the engine

Voices are independent node trees, so a ducker can't reach the kick's nodes.
The evaluator makes a `Bus` per slot name that's ducked under; the session
sends `Command::Bus { slot, bus }` once per name. Each block the engine renders
the voices of those slots *first*, copying their level into the bus, then the
rest, so a ducker reads the kick of the same block (no latency).

A node doesn't know where in the block its frames fall. Once running, a ducker
keeps count, which is exact; on its very first call it assumes it's asked for
the end of the block (true for a voice starting mid-block, and for a `delay` or
the later part of a `seq`). The worst case is a duck off by part of a block, on
its first block.

## Controls: random, range, round; glide

```
random(1b)                  -- a new value (0..1) every beat, held in between
random(1b).range(1, 5)      -- 1..5, continuous
random(1b).range(a3, c4)    -- whole notes: a3, a#3, b3 or c4, equally likely
random(0.25b).range(0, 12).round
modulation("lfo").range(200hz, 2khz)   -- any control, not just random
pattern.glide(150ms)        -- legato: connected notes slide
```

- `random` is a function of time (a hash of the period's number), like a
  modulation, so it follows the same clocks: free-running by default (each
  note picks the stream up where it is), `.latch` (the value at note-on,
  held), `.retrig` (a new stream per note).
- `range(lo, hi)` maps 0..1 onto lo..hi. Between two pitches it counts whole
  notes, both ends included; otherwise it's continuous (`.round` for whole
  numbers). Probabilities fall out of it: a hit that plays 70% of the time is
  `hat.gain(random(0.25b).latch.range(0.2, 1.2).round)`. (A `chance(p)` would
  read better.)
- **Glide** makes a pattern legato: a run of hits and ties up to a rest is
  *one* voice (one envelope attack), whose `?note` is a `NotePath` control
  sliding in a straight line (in notes) from each note to the next over the
  glide time. A rest ends the phrase; a phrase can run on into the next pass;
  a pattern with no rests at all is one endless voice. Like a mono synth with
  glide in legato mode.

## Functions

```
fn filter_delay(node) = add(
  node,
  node.bandpass(?low = 500hz, 0.3).echo(0.5b, 0.6, 1).pan(-1),
  node.bandpass(?mid = 1.2khz, 0.3).echo(0.75b, 0.5, 1),
  node.bandpass(?high = 3khz, 0.3).echo(1b, 0.6, 1).pan(1),
)
blip.filter_delay.play                        -- x.f is f(x), as for built-ins
blip.filter_delay.with(low: 300hz).play       -- holes in the body are holes in the result
fn triad(x, third, fifth) = add(x, x.with(note: ?note + third), x.with(note: ?note + fifth))
```

- `fn name(params) = expression`: a statement, like `let`, and the body is
  one expression. The arguments are evaluated first, then the parameters are
  bound (shadowing any `let` of the same name) while the body is evaluated.
- Two kinds of parameters, kept apart as decided on 3 October: a function's
  parameters are filled when the code runs and can be anything (sounds,
  durations, strings); holes in its body (`?low`) stay holes in the sound it
  returns, filled later with `.with` or by a pattern, and can be modulated.
- Names in the body are looked up when it's *called* (dynamic scope): a
  function sees the `let`s and functions there are by then, so redefining a
  helper changes what uses it, and functions can call each other in any
  order. Runaway recursion stops after 64 nested calls.
- The body was parsed from whichever code defined it, so its positions mean
  nothing in the code being run: an error inside a body is reported at the
  call, with the function's name in front (`wide: spread: expected ...`).
- A function can't take a built-in's name. Not yet: several statements in a
  body (local `let`s), default parameters, type annotations, or passing
  functions as arguments.
- cmd-. doesn't look inside function bodies for slot names: defining a
  function isn't playing it.

## Offline rendering

```
cargo run -p rocktober-repl -- render journey.rock 30s          -- recordings/journey.wav
cargo run -p rocktober-repl -- render dnb.rock 16bars out.wav
```

Runs the whole file (as cmd-shift-enter would) in a `Session::without_output`
and renders the length (`30s`, `1:30`, or beats at the file's tempo) as fast as
it can: `Session::render` takes turns doing the scheduler's work and the audio
thread's, exactly as live. About 6× faster than real time for `journey.rock`.
The WAV is the same format as recordings.
